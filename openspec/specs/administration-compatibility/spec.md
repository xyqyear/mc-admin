# administration-compatibility Specification

## Purpose

在替换内部实现边界的过程中，确保现有 Minecraft 管理流程、集成契约和已存储数据保持可用，并为部署升级及回滚保留可核验的兼容边界。

## Requirements

### Requirement: Existing administration contracts remain usable

**现有管理契约保持可用**

除本变更明确列出的正确性修复外，系统必须（SHALL）保留已支持的 HTTP 路由、认证和角色规则、CSRF 保护、响应字段、现有错误详情结构及有意义的字段，以及现有 SSE/WebSocket 协议。提示文案修正必须（SHALL）保留与客户端有关的语义，并明确记录。现有标识符、模板、快照引用、服务器目录和部署挂载必须（SHALL）保持可用。

#### Scenario: 现有集成继续管理服务器
- **WHEN** 现有客户端通过受支持的 cookie 或 master-token 流程读取配置、提交操作并观察结果
- **THEN** 该操作仍可通过既有协议和标识符使用
- **AND** 未认证或权限不足的请求仍被拒绝

#### Scenario: 升级受支持的已部署数据库
- **WHEN** 安装实例使用受支持的版本化数据库及现有服务器、备份目录进行升级
- **THEN** 服务器身份、保留的玩家历史、模板快照、计划和恢复引用仍可访问
- **AND** 对存在歧义的历史记录报告问题，不悄然重新分配或删除

#### Scenario: 上传偏移量冲突
- **WHEN** 断点续传在错误的偏移位置提交分块
- **THEN** 冲突响应在受支持的结构化错误详情中保留服务端权威偏移量和有意义的提示
- **AND** 前端错误归一化不会丢弃该偏移量

### Requirement: Operation ownership preserves cancellation semantics

**操作归属保留原有取消语义**

系统必须（SHALL）保留依附请求执行的有限流、独立后台任务和浏览器传输之间的区别。关闭依附请求执行的恢复流必须（SHALL）中断执行并保留恢复信息。离开独立后台任务所在页面，本身不得（SHALL NOT）导致该任务取消。

#### Scenario: 离开恢复页面
- **WHEN** 离开页面导致正在执行的请求所属恢复流关闭
- **THEN** 执行被中断，必要清理完成，保留的历史记录仍支持既有恢复流程

#### Scenario: 离开重建页面
- **WHEN** 独立后台重建已被受理后，用户离开页面
- **THEN** 后台任务按照现有执行归属策略继续运行
- **AND** 任务中心可以观察到最终结果

#### Scenario: 取消普通多文件上传
- **WHEN** 部分文件已经写入后，用户取消普通文件上传
- **THEN** 后续批次停止，已经写入的文件按照现有部分上传策略保留
- **AND** 文件列表与实际结果同步

#### Scenario: 取消尚未发布的压缩包上传
- **WHEN** 压缩包上传会话在校验发布前被明确取消
- **THEN** 按照现有会话契约清理其尚未发布的临时资源
- **AND** 压缩包只有在哈希校验及发布成功后才出现在已发布列表中

#### Scenario: 浏览器执行状态丢失
- **WHEN** 浏览器刷新导致活动传输执行状态和本地文件句柄丢失
- **THEN** 保留的任务元数据不会错误地声称传输仍在继续，或无需必要的本地输入即可自动恢复

### Requirement: Ordinary administration remains available during normal operation

**正常运行期间保留普通管理能力**

系统必须（SHALL）保留当前已支持的在线操作，包括世界数据之外的普通文件恢复、文件编辑、控制台使用及读取。操作协调机制必须（SHALL）仅在受影响资源与活动操作的安全要求冲突时限制操作。

#### Scenario: 服务器运行时恢复普通文件
- **WHEN** 用户恢复世界目录之外的配置或插件文件，且不存在冲突的维护操作
- **THEN** 现有在线恢复流程仍可使用

#### Scenario: 世界维护期间读取数据
- **WHEN** 维护操作占用世界的破坏性写入范围
- **THEN** 状态、进度及其他安全读取仍可使用
- **AND** 维护不会施加无关的全局读锁

### Requirement: Publication uses verified application artifacts

**发布使用经过验证的应用产物**

发布的应用镜像必须（SHALL）能够追溯到通过必要静态检查和回归门槛的代码版本及镜像产物。任何必要检查失败都必须（SHALL）阻止发布。

#### Scenario: 发布候选版本的测试失败
- **WHEN** 发布候选代码版本或其构建镜像的某项必要检查失败
- **THEN** 该候选版本不会作为已验证版本发布

#### Scenario: 发布经过验证的镜像
- **WHEN** 发布候选版本通过全部必要检查
- **THEN** 发布流程晋升已验证的镜像 digest，不替换为独立重新构建的应用产物
