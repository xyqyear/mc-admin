## Why

重启计划按具体服务器实例代次绑定，会阻止名称与参数不一致、创建时间早于服务器登记或跨同名实例的有效历史计划注册。业务需要根据计划参数中的服务器名执行，保留原来的配置和执行历史。

## What Changes

- 重启计划每次执行根据参数中的完整服务器名定位当前服务器，显示名称不决定目标。
- 服务器页面保留受管用途分类，优先管理最早建立的未取消匹配计划；全部取消时展示最新取消计划供用户明确重新启用。多个历史计划保持独立。
- **BREAKING** 删除 cron API 的实例绑定字段和绑定错误字段及仅用于绑定的注册状态；移除对应前端提示。
- 新数据库迁移删除实例绑定列和约束，保留已有计划字段、状态、ID 和执行历史。
- 保留暂停、取消、删除时取消活动计划，以及单次执行的资源锁、当前实例复核和停止服务器跳过行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `operation-consistency`: 明确重启计划按参数中的逻辑服务器名识别，保留精确匹配及单次操作安全边界。

## Impact

涉及后端 cron、服务器重启计划服务、数据库迁移、前端任务详情和契约、API E2E 及相关规范文档。Docker 管理协议、快照与恢复的实例保护保持现有契约。本次不部署或修改线上服务器，不发布新的应用版本。
