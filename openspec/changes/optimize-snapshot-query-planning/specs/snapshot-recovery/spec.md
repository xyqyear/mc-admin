## ADDED Requirements

### Requirement: 候选快照查询保持响应且不改变恢复判断

系统必须（SHALL）在多区域选择和较多历史快照下保持其他管理请求可响应。候选快照的内容、顺序、跳过路径及总数必须（SHALL）继续遵守现有覆盖、逻辑忽略、源身份和缺失记录规则；查询不得（SHALL NOT）创建恢复任务、安全快照或修改世界数据。

#### Scenario: 查询多个区域的历史快照
- **WHEN** 管理员在包含数百份快照的仓库中查询多个区域的候选快照
- **THEN** 查询期间其他管理读取可以完成，候选结果包含适用来源和准确的跳过证据

#### Scenario: 受保护的附属文件
- **WHEN** 选择涉及当前或历史规则中被忽略的 MCC
- **THEN** 系统保持对应的忽略规则，包括文件当前不存在及负坐标区域的情况

#### Scenario: 关闭未完成的候选列表
- **WHEN** 管理员关闭列表或切换选择使原候选查询失去观察者
- **THEN** 客户端取消过时查询，服务端在观察到断开后停止该查询并完成所拥有读取进程的清理
- **AND** 再次打开列表可以独立完成新查询，不取消已受理的恢复任务

#### Scenario: 查询鉴权失败或仓库读取失败
- **WHEN** 查询没有有效身份或仓库无法读取
- **THEN** 系统保留现有权限和失败响应，不返回伪造的空列表或产生恢复写入
