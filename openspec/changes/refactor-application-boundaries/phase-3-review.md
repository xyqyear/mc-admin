# 第 3 组：运行时和操作归属验收

本轮完成任务 3.1–3.10，整体进度 **26/56**；第 4–7 组继续保留在任务清单中。实施内容、验证结果和资格边界记录如下。

## 用户可观察的结果

- 保留已有路由、任务状态枚举、SSE 事件格式和普通在线文件恢复。任务取消会立即通知实际执行者，界面在收尾结束前保持运行状态。
- 重启后可查看持久化的任务、cron 和恢复中断记录；不会自动重放删除、恢复或配置变更。
- 恢复问题按服务器实例代次隔离。不能确认写入已经停止或配置来源不一致时阻断对应写操作；其他服务器和安全读取继续可用。
- 地图缓存清理失败会使相关缓存不可用，但不会永久冻结整个服务器。后续成功清理可以解除降级。
- 磁盘上存在目录不再等同于已登记的服务器；接管是显式操作。删除后重新创建同名服务器得到新的实例代次。
- 新增操作历史查询，以及需要 OWNER 和正常 CSRF 校验的恢复解除接口。解除前再次验证写入归属、实例代次和必要的配置一致性，不能强制跳过检查。
- 手动启动、重启、停止、下线和定时重启记录 Docker 操作归属。CLI 取消不被当成 Docker 后台操作已停止的证明；不确定结果在释放维护租约前设置阻断，停止/下线仍可用于恢复。

## 结构设计

| 责任 | 当前实现 |
| --- | --- |
| 应用构建和资源生命周期 | `create_app`、独立 `Runtime`、兼容导入代理、启动恢复与逆序清理 |
| 服务器身份和路径 | `ServerRef`、数据库 ID 作为实例代次、ACTIVE 名称唯一、受限路径解析 |
| 操作准入和资源协调 | 冻结新写入、原子申请全部声明资源、等待/拒绝/跳过策略、经过校验的父租约复用 |
| 持久化操作证据 | 容量有界的 journal，受理/阶段/终态、执行者、资源影响和恢复引用 |
| 执行和收尾 | 直接取消工作任务，登记后才放行外部进程，验证进程句柄，等待有限线程与子进程收尾 |
| 重启恢复和兼容投影 | 启动生产者前核验遗留写入、按范围阻断、缓存降级，以及旧 task/cron/restoration 状态投影 |

兼容代理用于保留现有导入边界，资源实例属于运行时；没有将全部旧模块一次性改成构造器注入。配置的完整应用事务、所有文件操作的资源声明、世界恢复拆分和裁剪预览新鲜度仍对应后续明确任务。

## 迁移与部署边界

- `2026092500` 保留服务器历史 ID，增加 ACTIVE 名称唯一性和 SQLite 自增代次。遇到历史重复 ACTIVE 名称会拒绝迁移，不自动选择或删除记录。
- `2026092501` 增加操作日志。活动操作、未确认写入、恢复阻断、降级缓存或未解决的恢复引用会阻止删除 journal 的降级。
- 支持每组数据库及服务器目录一个后端写入进程。第二个共享任一资源的后端启动会失败；独立安装仍可并行。
- Linux 进程身份包含启动时刻、启动 ID、进程组和根目录标识；信号通过验证过的 pidfd 发送，不依据重新发现的裸 PID 杀进程。
- 本轮迁移和破坏性场景均运行于临时数据库或独立 E2E 环境，没有迁移实际应用数据库、发布镜像或提交 commit。
