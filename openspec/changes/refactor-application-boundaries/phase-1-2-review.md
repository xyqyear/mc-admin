# 第 1、2 组实施与验收记录

本轮范围是先建立可信基线，再修正已确认的边界问题。后续运行时装配、领域模块迁移、持久化操作日志和浏览器发布门槛仍按第 3—7 组推进。

## 用户可见结果

| 流程 | 本轮结果 |
| --- | --- |
| 文件、Compose、模板和动态配置编辑 | 初始内容未成功加载时不能误保存空值；有效会话中允许有意清空文件；保存失败、比较和远端刷新保留草稿；显式重新载入采用最新远端内容。 |
| 网络与错误反馈 | 前端统一消费 `ApiError`，保留结构化 `detail`；永久客户端错误不反复重试；刷新失败不显示成功；临时网络/服务错误不再直接把用户送回登录页。 |
| 服务器重启计划 | 按规范名称、任务类型和 `params.server_id` 精确识别；前缀相似服务器及独立命名的自定义 cron 不受影响；历史歧义明确返回 409。 |
| 玩家会话 | 并发重复上线只产生一个未结束会话；重复离线不能覆盖第一次记录的结束时间或重复计算时长。 |
| 维护操作 | 重建和定时重启加入现有维护互斥；定时重启遇维护或停服记录 `skipped`，不伪报已完成重启。 |
| 删除服务器 | 先冻结新的冲突写入，再等待后台任务；30 秒未结束则返回 409。请求拥有的恢复、直接文件/配置写入、地图初始化及渲染清理也参与保护。拒绝后保留服务器，操作结束后可重试。 |
| 凭据与异常 | 关闭 SQL 参数输出；意外 HTTP/任务/快照 SSE 异常使用安全消息和类型/调用位置日志。显式业务错误保留现有响应契约。审计强制脱敏 YAML、模板和文件正文，保留操作元数据。 |

## 可供审核的设计落点

- [用户旅程与兼容契约](../../../backend/docs/administration-contracts.md)：用户流程、角色/CSRF、响应与事件、取消和部署边界，以及对应回归负责人。
- [测试与基线](../../../backend/docs/testing.md)：隔离目录、能力标记、自动收集/分片审计、真实发布数据库、API/schema 和工作负载。
- [删除和生命周期](../../../backend/docs/servers.md)：准入冻结与执行互斥分离，避免等待任务时持有任务自己需要的锁。
- [数据库迁移](../../../backend/docs/database-migrations.md)：唯一索引、重复会话的离线预检/审核/修复及降级边界。
- [API E2E 覆盖](../../../e2e/docs/coverage.md)：每个新增场景实际验证的业务效果，区别于仅访问路由。

核心实现是 `app.operation_admission`、`app.world.locks` 和请求级依赖，仍沿用现有服务入口；前端仅提取了小型编辑会话 hook 和共享错误/重试策略。这些边界为下一阶段迁移提供回归保护，尚不代表完整的操作协调器或领域拆分已经完成。

## 测试证据

- 前端：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过；12 个测试文件、42 项用例。新增行为测试使用真实 QueryClient 与 HTTP 适配器边界。
- 后端完整无 Docker 集合初轮：1756 项通过、7 项失败、10 项未选中，5 条警告，耗时 853.76 秒。6 项失败来自填充测试的旧夹具访问真实 Docker，被新增隔离保护拦截；另 1 项 YAML 测试仍要求返回原始解析异常。已分别修正夹具的适配器边界和安全错误断言，全部受影响模块纳入下面的最终复核；修复后未再次运行完整集合。
- 后端定向最终复核：103 项通过，包含创建/填充、API 契约、并发保护、HTTP/任务/SSE 错误及审计脱敏；Pyright 和 Ruff 均通过。
- 故障注入：旧的子串计划匹配、非原子会话创建、失效的时间限制和审计判断均使新增测试失败；错误处理和草稿测试也先复现失败，再验证修复。
- CI 收集：曾对实际 21 个分组的 1770 个 node ID 做独立并集审计，无遗漏或重复；这是该次收集的记录，并非固定测试数量或覆盖率门槛。
- Docker 夹具：真实创建带随机归属标签的容器/网络，验证标签后按完整 ID 清理，重复清理成功，最终确认对应 ID 不存在。
- Go：格式、vet 和 race 检查通过。
- API E2E：最终候选镜像上的 10 个相关场景分别完成普通模式及 `--no-reuse` 验证，后者整轮 10/10 通过。涵盖精确计划、重复会话迁移与上下线、恢复维护、删除排空、凭据日志、解压错误、任务历史及 Compose 转换。

普通模式首次新增凭据用例把已有显式 HTTP 错误误当作未处理异常；实现按兼容契约保留了其 detail。用例改为真实 Restic 非法快照触发的未处理 HTTP/SSE 异常后通过。保留原失败报告，不把它算作成功。

## 上线前与下一阶段边界

升级前应在数据库副本上运行重复会话预检。存在重复时迁移明确拒绝启动，必须审核报告后显式修复。策略保留最早加入时间的规范会话，其余重复行保留历史 ID、按零时长结束，并保存修复前后证据；降级索引不会自动撤销历史修复。本轮只在可丢弃数据库中演练，未修改实际部署数据。

生产约束仍为单进程写入；任务仍在内存中，取消仍需等待执行器清理。配置的原子提交、并发版本冲突和持久化操作恢复属于后续阶段。下一步是第 3 组的应用装配与运行时归属，应在这些行为基线之上逐项迁移。

性能基线使用本机 fd 10.3.0、Restic 0.18.0 和 mcmap 0.8.4，四类合成工作负载的行为计数前后一致。候选镜像使用 Dockerfile 固定版本。记录的时间受共享机器和进程内 HTTP 影响，不把它们当成正式性能验收结论。
