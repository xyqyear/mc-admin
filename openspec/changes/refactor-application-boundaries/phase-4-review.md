## 用户可观察的行为

- GET Compose、模板配置及转换比较提供 `version`；配置写入接受可选 `expected_version`，过期请求返回 409 和 `configuration_conflict`。新版界面始终提交已观察到的版本。
- 比较与刷新不会替换用户草稿。保存成功只确认本次提交对应的版本，保存期间继续输入的草稿仍保留；随后出现更晚的远端版本仍要求比较。
- 后台任务离开页面后继续运行，完成后返回页面会获取新的配置和状态。重连时已经被保留策略清理的旧任务也会触发保守同步，而不会永久阻塞观察器。
- 直接模式与模板模式之间保留原始编辑、差异对比、重置、变量提取和语义相等时免重建的转换。元数据转换也经过资源占用、版本复检和操作日志。
- 启动失败不会抹掉已写入的配置与匹配来源。来源提交失败不会继续启动，也不会把已发生的文件写入描述为回滚。
- 受管计划 CRUD 根据实例归属操作；显示名称不决定归属。删除服务器仍按原业务语义取消该实例相关的活动重启任务，独立任务不会因此被重新归属给同名新实例。

## 故障与恢复证据

配置服务测试在准备、暂存、停服前后、替换前后、来源保存前后和启动前后注入失败，断言文件、来源、运行意图、阶段和阻断状态。另覆盖实际文件替换失败、来源事务回滚、Docker 命令失败、取消时文件线程仍未结束、暂存权限及收尾失败后的再次启动清理。

暂存文件创建时采用 0600 权限，随后保留目标文件的所属用户、组及权限。Compose 指向项目内部文件时，在其实际目标旁暂存。操作日志保存准确的受限相对路径；恢复不会跟随已经重定向的父目录，也不会清理同名新实例的文件。

确认写入结束后，没有发生修改的中断操作不会要求把原配置改成尚未应用的目标配置。发生修改时，仅在现场与记录的原始基准一致，或目标内容与目标来源均一致时，允许解除配置恢复限制；不自动重放配置应用或启动服务器。

## 保留的运行限制

- 单数据库及受管服务器根目录仍要求单后端写入进程。文件、SQLite 与 Docker 不构成跨系统原子事务；操作日志保存阶段和恢复证据。
- 版本检查能够检测读取和最终检查时已经发生的外部编辑，无法与任意外部文件写入者建立原子 CAS。应用期间仍应避免其他程序同时编辑 Compose 或直接修改 Docker 状态。
- 配置出现已知不一致时，需要核对并恢复已记录基准或完成目标来源协调，再由 OWNER 调用恢复验证接口；不会提供忽略身份和一致性的强制成功入口。
- 数据库升级采取增量迁移。回滚应用前必须停止新操作并排空运行工作，且只回退到已验证支持当前 schema 的版本；恢复数据库副本不等于撤销已发生的文件或世界修改。
- 本会话没有可调用的 IDE diagnostics 工具；Pyright、Ruff 和 TypeScript/ESLint 结果单独记录。
