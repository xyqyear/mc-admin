# 第 6 组：领域边界与状态协调验收

本组覆盖任务 6.1–6.8。业务仍通过现有页面、HTTP API、WebSocket 和 SSE 使用；实现将状态与资源归属移入相应功能模块。本组实现与规定验证已完成；第 7 组的发布验收另行进行。

## 模块归属

- 玩家：`players/service.py` 统一日志、RCON 校准和心跳恢复使用的身份/会话入口。生产者共享所属运行时的数据库、身份解析、名称过滤及事件发布能力；保留 usercache 优先、Mojang 校验、历史游标和落库后发布的顺序。
- 计划任务：cron 调用 `servers/commands.py` 的公共命令。保存的启用/暂停状态与调度器实际注册状态分开；无法注册的历史计划仍可见。触发器执行前核对最新计划定义，停服服务器的定时重启记为跳过。执行开始和终态持久化，启动时只标记中断历史，不重放命令。
- 网络连接：`dns/planning.py` 负责期望记录和增量差异；客户端负责服务商与路由的读取和应用。无法读取时返回未知状态，不伪装为零条记录。局部故障保留健康端的处理能力，重试会重新观察实际状态；目标为空或服务器配置不确定时保留既有记录，防止错误删除。
- 身份、设置与健康：服务构造时捕获所属运行时的数据库及配置视图。切换其他应用的上下文不会改变已创建服务的资源归属。配置在行为发生时读取最新缓存；健康检查与通知接收方分别隔离故障，保存结果与错误日志排除未经筛选的异常内容。
- 前端：各功能的契约、查询、命令和界面位于 `features/`；应用组合位于 `app/`，通用传输和 UI 位于 `shared/`。聚合页面复用查询选项；删除重复任务 store，玩家资料流更新 Query 缓存。计划注册失败与 DNS 降级、未知、空配置均有用户可见提示。

## 持久化与公共契约

原 `app/models.py` 中的 27 项定义分别归入身份、服务器、玩家、cron、自检、设置、模板、世界及数据库基础模块；路由中的共享 DTO 移入对应功能。`app/db/metadata.py` 显式注册 Alembic 使用的全部表。针对拆分前后定义生成 SQLite 表和索引 DDL，既有 15 张表及索引定义一致，操作日志表仍注册。本组不需要新增数据库迁移。

保留公开路由、原有状态枚举和响应字段；cron 注册状态及 DNS 观察状态采用新增字段。四个因内部模块迁移而可能变化的 OpenAPI 同名类型引用由 `api_schema.py` 保持原公开名称。前端身份 DTO 从隔离应用的真实 OpenAPI 完整依赖闭包生成；动态任务结果和流事件继续使用显式运行时校验。

`runtime_factories.py` 集中构造实际资源，类型明确的访问函数返回所属运行时对象。删除导入时工厂注册、全局资源代理和隐式默认运行时；HTTP、流、后台任务、测试及命令入口必须明确绑定所有者。可执行导入规则限制领域依赖路由、跨模块内部引用和旧兼容入口。

## 保留的运行边界

每个数据库与受管服务器目录仍只支持一个后端写入进程。中断操作不会自动重放；未知写入者的恢复阻断和临时产物保留策略继续生效。DNS 与路由的外部应用不具有跨服务事务，局部成功后通过重新观察进行后续协调。前端完整浏览器流程、最终发布门槛、工作负载对比及部署回滚演练属于第 7 组。
