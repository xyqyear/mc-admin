## MODIFIED Requirements

### Requirement: Existing administration contracts remain usable

**现有管理契约保持可用**

除明确列出的接口迁移和正确性修复外，系统必须（SHALL）保留已支持的 HTTP 路由、认证和角色规则、CSRF 保护、响应字段、现有错误详情结构及有意义的字段，以及现有 SSE/WebSocket 协议。快照创建、预览、恢复、回滚及仓库维护必须（SHALL）迁移为统一任务接口，前后端同批部署，不保留被替换的旧同步/SSE 执行及重复世界恢复路由。提示文案修正必须（SHALL）保留与客户端有关的语义，并明确记录。现有标识符、模板、快照引用、服务器目录和部署挂载必须（SHALL）保持可用。

#### Scenario: 现有集成继续管理服务器
- **WHEN** 客户端通过受支持的 cookie 或 master-token 流程读取配置、提交操作并观察结果
- **THEN** 除已明确迁移的快照接口外，操作仍可通过既有协议和标识符使用
- **AND** 未认证或权限不足的请求仍被拒绝

#### Scenario: 升级受支持的已部署数据库
- **WHEN** 安装实例使用受支持的版本化数据库及现有服务器、备份目录进行升级
- **THEN** 服务器身份、保留的玩家历史、模板快照、计划和恢复引用仍可访问
- **AND** 对存在歧义的历史记录报告问题，不悄然重新分配或删除

#### Scenario: 上传偏移量冲突
- **WHEN** 断点续传在错误的偏移位置提交分块
- **THEN** 冲突响应在受支持的结构化错误详情中保留服务端权威偏移量和有意义的提示
- **AND** 前端错误归一化不会丢弃该偏移量

#### Scenario: 同批前后端使用新的快照接口
- **WHEN** 用户通过文件管理器或地图发起快照操作
- **THEN** 前端提交统一任务接口并观察结果，旧快照执行路由不再暴露
- **AND** 与快照执行无关的地图读取、认证和 CSRF 规则保持可用

### Requirement: Operation ownership preserves cancellation semantics

**操作归属明确执行与观察的取消语义**

系统必须（SHALL）保留依附请求执行的有限流、独立后台任务和浏览器传输之间的区别。快照相关耗时操作必须（SHALL）由独立任务执行，关闭观察连接或离开允许离开的页面不得（SHALL NOT）导致任务取消。原有阻塞范围和禁止关闭的执行面板必须（SHALL）保持到实际终态；显式任务取消必须（SHALL）停止可终止执行并保留恢复信息。

#### Scenario: 离开恢复页面
- **WHEN** 已受理恢复任务后，用户刷新或执行界面原本允许的导航
- **THEN** 任务继续运行，恢复历史与任务中心可见结果，重新进入可恢复观察
- **AND** 原本不允许关闭的执行面板不会因拿到任务 ID 而提前允许关闭

#### Scenario: 离开重建页面
- **WHEN** 独立后台重建已被受理后，用户离开页面
- **THEN** 后台任务按照现有执行归属策略继续运行
- **AND** 任务中心可以观察到最终结果

#### Scenario: 取消普通多文件上传
- **WHEN** 部分文件已经写入后，用户取消普通文件上传
- **THEN** 后续批次停止，已经写入的文件按照现有部分上传策略保留
- **AND** 文件列表与实际结果同步

#### Scenario: 取消尚未发布的压缩包上传
- **WHEN** 压缩包上传会话在校验发布前被明确取消
- **THEN** 按照现有会话契约清理其尚未发布的临时资源
- **AND** 压缩包只有在哈希校验及发布成功后才出现在已发布列表中

#### Scenario: 浏览器执行状态丢失
- **WHEN** 浏览器刷新导致活动传输执行状态和本地文件句柄丢失
- **THEN** 保留的任务元数据不会错误地声称传输仍在继续，或无需必要的本地输入即可自动恢复
