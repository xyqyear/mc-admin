# 第一轮：非快照耗时操作后台化

状态：已实施并完成本地回归，验证范围和环境记录见 [`verification.md`](verification.md)。下一轮快照需求单独记录在 [`docs/snapshot-recovery-roadmap.md`](../../../../docs/snapshot-recovery-roadmap.md)。

## 用户能看到的变化

点击操作后及时展示正在做什么，任务中心同时可以查看。原来阻塞界面的流程继续阻塞，原来的流式进度界面继续展示进度，只把状态来源改为任务状态查询。拿到任务 ID 不代表完成，不能因此解除按钮禁用、关闭弹窗或自动跳转；这些行为仍按原流程，在任务实际结束后处理。

操作按钮旁显示一行原因，例如“正在准备镜像和容器 · 查看任务”，避免只剩灰色按钮。原来禁止关闭的执行中弹窗仍然禁止关闭，原来允许离开的页面保持原规则。如果浏览器刷新、断网或页面卸载，已经受理的任务继续执行，返回后重新获取状态。读取状态失败时提示连接问题，不误报任务失败或完成，也不因此允许重复提交。

有可靠计数时展示百分比，否则展示阶段和耗时。Docker 启动任务完成与 Minecraft 已就绪分别显示，不提前声称服务器已经可以游玩。

## 本轮覆盖

| 操作 | 处理 |
| --- | --- |
| 启动、停止、重启、下线 | 接入后台任务，显示执行阶段 |
| 创建、删除服务器、同步服务器登记 | 接入后台任务，保留结果与现有校验 |
| 服务器文件和存档目录的递归删除 | 接入后台任务，保留路径保护和清理边界 |
| 地图初始化、强制重新准备地图资源 | 接入后台任务，沿用真实下载和生成进度 |
| 手动全量／单项自检、手动 DNS 同步 | 接入后台任务，保留检查结果和失败原因 |
| 上传完成后的服务端 SHA256 计算与发布 | 接入后台任务，保护上传输入，发布完成后才确认成功 |
| 已经后台化的重建、解压、压缩、权限修复、区块清理 | 核对展示和完成刷新，不重复包一层任务 |

快照创建、恢复、恢复预览、回滚以及快照仓库维护全部留到下一轮。普通查询、控制台交互、浏览器传输文件内容、同目录重命名等即时交互保留现有方式。

## 实施原则

- 复用现有后台任务、操作日志和任务中心；各功能写清楚自己的执行流程，不新建通用工作流框架。
- 后台化不能绕过停服、权限、路径和服务器实例校验，也不能提前释放维护锁。
- 删除服务器需要排除“等待自己的删除任务”的死锁；创建和同步需要正确处理尚未登记和涉及多台服务器的目标。
- 支持安全取消的操作才提供取消按钮；仅对原来允许关闭的面板，关闭才停止观察，不取消任务。原有关闭限制保持不变。取消不等于自动回滚，后端重启不自动重放破坏性操作。
- 前后端同时部署，直接使用任务受理和状态查询接口；删除未使用的旧同步／流式接口及适配代码，不保留旧客户端兼容层。

实施顺序：任务受理与身份边界 → 服务器生命周期 → 文件与地图 → 自检／DNS／上传校验 → 保留原有阻塞交互并接入任务状态 → 真实回归测试。
