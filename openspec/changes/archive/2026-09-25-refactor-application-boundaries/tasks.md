- [x] 1.3 用具有明确资源归属的测试夹具替换固定临时路径及缺少归属验证的固定名称 Docker 清理；引入能力标记，验证“无 Docker”测试集合不会执行 Docker 清理。

- [x] 1.6 建立有代表性的 API/schema 夹具、受支持发布版本的迁移夹具和工作负载测量基线；夹具不得包含秘密或真实用户数据。
- [x] 1.7 为每项计划中的后端可观察行为修复增加 API E2E 场景，并更新 e2e/docs/coverage.md；继续区分路由访问覆盖与业务断言覆盖。

## 2. 在迁移前修正现有流程边界

- [x] 2.1 将受管计划的子串查询替换为精确服务器归属查询，覆盖 GET/更新/暂停/恢复/删除；验证独立创建的 cron 任务不受影响。
- [x] 2.2 在可丢弃的历史数据副本上设计并测试重复未结束会话的预检和修复，保留修复证据及历史 ID；明确唯一有效的未结束会话应如何确定。
- [x] 2.3 增加会话唯一性迁移和原子化会话获取；验证并发上线、重复离线、迁移失败/回滚，以及在线时长不重复计算。
- [x] 2.4 使用共用命令策略补齐重建和定时重启的维护保护；增加通过同步屏障控制执行交错的恢复/裁剪并发测试。
- [x] 2.5 删除操作在取消超时后仍有写入未结束时必须拒绝继续，并立即阻止删除期间的新冲突操作进入；安全检查需包含依附请求执行的恢复操作。
- [x] 2.6 禁止输出包含秘密的 SQL 参数，并统一用户可见异常处理，同时保留现有字符串及结构化 detail 契约；使用合成凭据验证部署中的所有日志输出通道。
- [x] 2.7 在加载、远端刷新和保存失败时保留编辑草稿；只有建立有效编辑会话后，才允许用户有意将文件保存为空。
- [x] 2.8 将错误处理方迁移到统一错误类型，修正重试和重新获取数据时的反馈；分别测试 401/403/409/422/5xx 和网络故障。
- [x] 2.9 运行针对性的后端 pytest/E2E、前端测试、后端 Pyright/Ruff 和前端 lint/typecheck；在结构迁移前记录已修正的契约。

## 3. 引入明确的运行时和操作归属

- [x] 3.2 为事件生产者、任务、渲染队列、预览会话、客户端和数据库资源实现启动清理栈及有序关闭；测试部分初始化失败。
- [x] 3.3 引入经过解析的服务器引用，包含实例代次和受限路径；验证历史名称、缺失/停用服务器、符号链接根目录、路径穿越输入，以及显式接管流程。
- [x] 3.4 实现操作准入、跨资源类别的确定性获取顺序和声明式冲突策略；嵌套安全备份复用经过校验的父操作资源租约，保留不同服务器及安全读取的并发能力。
- [x] 3.5 分离删除期间的准入冻结与执行期资源占用；测试排队/运行任务、取消、超时，以及最终删除前不会死锁的任务排空。
- [x] 3.6 新增操作日志数据库迁移及容量有界的存储层，记录受理、阶段、终态、执行者、资源影响和恢复引用；排除秘密及大体量进度数据。
- [x] 3.7 将执行器的取消机制连接到外部适配器和必要收尾操作；测试无输出子进程、有限流、清理失败及终态发布顺序。
- [x] 3.8 增加任务/cron/恢复的兼容映射，使现有状态字符串和 SSE 结构保持可用；在不破坏旧枚举的情况下区分内部中断结果。
- [x] 3.9 在启动事件生产者和开放操作准入前处理已中断操作；验证所属写入任务已结束、按资源范围设置的恢复阻断及解除条件、缓存降级不会永久阻断服务器、不自动重放破坏性操作，以及受支持的单写入进程部署边界。
