## Why

MC Admin 已经支持较完整的管理流程，但流程状态和副作用的职责分散在路由、调度器、单例服务及页面组件中。本次重构将明确这些边界，避免新增流程时再次引入导致数据丢失的并发冲突、服务器目标错选、编辑草稿丢失或误导性的完成提示。

## What Changes

- 保留单一应用镜像、现有 Python/React/Go 技术栈及管理能力；将实现组织为模块化单体，明确应用服务和基础设施适配器的职责。
- 让手动操作、配置重建、定时操作、恢复、裁剪和删除共用操作准入及资源占用管理。保留依附请求执行的流式操作与独立后台任务之间的区别。
- 让破坏性操作在取消或进程中断后仍有可追溯的结果和清理状态。新增容量有界的持久化操作日志，同时保留现有任务与恢复 API 的适配层。
- 为服务器计划和玩家会话建立明确的身份关系及数据库不变量，修复已复现的计划子串匹配和并发重复会话缺陷。
- 按业务功能组织前端代码，集中处理任务完成后的缓存同步，统一传输错误，并为文件和 Compose 编辑器建立明确的草稿会话。
- 保留现有 Go API E2E 框架。加强隔离的服务测试和外部适配器契约测试，补充少量浏览器用户流程测试，并让镜像发布依赖对待发布的确切版本和产物的检查。
- 通过兼容的接口，每次迁移一个完整流程。将行为修正与内部代码搬迁分别标明，每个阶段都提供回归证据和回滚边界。

**目标：** 在保留产品功能范围的前提下，让现有用户操作保持一致、易于测试且便于扩展。

**非目标：** 多宿主机管理、微服务、通用工作流或插件引擎、引入 Redis/Celery、新 UI 设计系统、替换 Restic/mcmap/Docker、改变角色模型，或让中断的破坏性操作自动续跑。

## Capabilities

### New Capabilities

- `administration-compatibility`：在替换内部实现时，保留现有管理契约以及部署和数据兼容性。
- `operation-recovery`：为具有重要影响的操作保留有意义的终态，并清理其占用的资源；不在用户不知情的情况下重新执行破坏性操作。

### Modified Capabilities

- `operation-consistency`：将维护期间的资源占用规则扩展到所有存在冲突的入口，保留编辑草稿和准确的完成反馈，按确切的服务器身份定位计划，并保证每个玩家与服务器组合最多只有一个未结束会话。

## Impact

- **后端：** 应用构建与生命周期、服务器生命周期及配置、cron、任务执行、世界恢复/快照/裁剪协调、文件操作边界、玩家会话、持久化职责，以及日志和错误策略。领域算法和已支持的集成继续复用。
- **前端：** 功能组织方式、查询与错误契约、编辑会话、操作进度和完成处理，以及文件、Compose 和世界页面。保留现有 URL、导航、中文界面和日常操作方式。
- **API：** 通过适配层保留现有方法、路径、认证和 CSRF 规则、JSON 结构（包括结构化错误详情）、状态语义及 SSE/WS 协议。操作日志和查询元数据采用增量扩展。对不安全并发、计划错选、虚假成功和草稿丢失的修正属于明确列出的行为修复。用户提示文案的修正需单独记录，不承诺历史错误文案逐字不变。
- **持久化：** 为操作记录和受管计划归属新增 Alembic 迁移，并在重复会话预检和修复后安全地施加唯一性约束。不重置已部署的数据库、服务器目录、快照、ID 或模板快照。对归属不明的历史计划报告问题，不猜测或删除。
- **Docker：** 保留现有镜像和挂载。明确当前隐含的后端单写入进程约束；不将进程内锁描述为支持多 worker 或多副本的方案。发布使用已经验证的产物。
- **测试与依赖：** 保留 pytest、Vitest 和独立 Go 执行器；建议仅将 Playwright 加入开发依赖，用于浏览器测试。确认 API schema 完整性后，再逐步引入 schema 或客户端生成工具。
- **兼容性：** 不计划进行破坏性的 API、配置或路径迁移。新增数据库约束和操作日志行为需要迁移演练及边界明确的回滚方案；本设计不承诺任意旧版本程序都能安全运行于未来所有数据库结构之上。

应用实现和数据库迁移已完成本地验收，正式发布及规范同步归档仍待完成。实施进度以[任务清单](tasks.md)为准，验收范围和限制见[第 7 组验收记录](phase-7-review.md)。
