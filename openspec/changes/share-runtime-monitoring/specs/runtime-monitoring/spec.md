## Purpose

为已登录用户提供共享、可判断新鲜度的服务器与宿主机监控结果，使多个页面和用户的观察不重复执行昂贵采样，并在实例替换、资源读取失败和操作执行期间保持数据身份、指标含义与管理安全一致。

## ADDED Requirements

### Requirement: Authenticated shared monitoring reads

系统必须（SHALL）通过统一监控读取提供受管服务器状态、资源指标和维护状态，以及宿主机资源指标。采样工作必须（SHALL）在观察者之间共享；读取不得（SHALL NOT）等待一个新的 CPU 计量窗口或目录遍历完成。读取范围必须（SHALL）遵守当前认证及服务器访问规则。

#### Scenario: 多个页面和客户端同时观察
- **WHEN** 多个已登录客户端同时读取相同服务器的监控数据
- **THEN** 客户端得到已有采样结果及对应时间，增加观察者不会为每个读取重新执行资源采样

#### Scenario: 未登录读取
- **WHEN** 未认证客户端请求监控数据
- **THEN** 请求被拒绝，不返回服务器或宿主机指标

#### Scenario: 单台服务器配置不可读
- **WHEN** 一台已登记服务器的配置读取失败
- **THEN** 该服务器报告不可用原因，其他服务器和宿主机数据继续可读
- **AND** 不把配置损坏解释为不存在的服务器，也不返回未受管容器的数据

### Requirement: Explicit sample freshness and partial failure

系统必须（SHALL）区分有效、等待首个有效样本、过期和不可用的数据，并保留各指标实际采样时间。接口返回时间不得（SHALL NOT）冒充采样时间；读取失败不得（SHALL NOT）伪装成零使用率、服务器停止或无维护任务。独立指标的读取失败必须（SHALL）局部降级。

#### Scenario: CPU 刚开始采样
- **WHEN** 当前进程尚未形成完整的计量区间
- **THEN** CPU 显示等待采样，不返回看似真实的零值

#### Scenario: Docker 暂时不可读
- **WHEN** 容器状态读取失败但存在旧样本
- **THEN** 返回带原始时间的过期样本和安全的错误说明，不确认服务器已经停止
- **AND** 不依赖 Docker 的宿主机指标仍可继续更新

#### Scenario: 大目录尚未统计完成
- **WHEN** 存档目录遍历尚未结束
- **THEN** 目录占用显示等待或过期数据，状态、CPU、内存和维护信息仍可独立读取

### Requirement: Preserve metric meaning and isolate instance identity

服务器 CPU 必须（SHALL）继续表示 Java 进程使用率，以一个逻辑核的全部计算能力为 100%，允许多核负载超过 100%。内存必须（SHALL）继续表示既有容器内存口径；磁盘及网络 I/O 必须（SHALL）保留既有累计字节口径。服务器代次、容器或 Java 进程发生替换时，系统必须（SHALL）隔离旧数据和新数据，重新建立需要差值的采样基线。

#### Scenario: 多核 Java 负载
- **WHEN** Java 进程在有效测量区间消耗相当于两个逻辑核的 CPU 时间
- **THEN** 服务器 CPU 可接近 200%，不被截断到 100% 或改成整个容器 CPU

#### Scenario: 服务器停止和重新启动
- **WHEN** 服务器停止后启动了新的 Java 进程
- **THEN** 停止期间相关运行指标明确不可用，新进程重新预热
- **AND** 展示新实例的累计 I/O 字节，不将新旧 CPU 计数器相减或展示旧进程 CPU

#### Scenario: 同名服务器重建
- **WHEN** 旧代次的慢速采样在同名新服务器建立后才结束
- **THEN** 旧结果不能覆盖新服务器数据或成为新服务器的差值基线

### Requirement: Monitoring does not authorize mutations

监控结果必须（SHALL）仅用于观察，修改操作必须（SHALL）继续使用执行时的权威准入、实例身份和实际运行状态校验。维护状态必须（SHALL）反映现有恢复阻塞、生命周期任务和维护所有者，不能仅从完成通知推断。监控数据、接受响应或观察断线不得（SHALL NOT）替代任务终态及必要清理确认。

#### Scenario: 缓存显示停止但服务器已启动
- **WHEN** 用户基于旧监控数据提交要求停服的世界修改
- **THEN** 后端按实际运行状态和现有准入规则拒绝冲突执行

#### Scenario: 另一客户端开始维护
- **WHEN** 另一客户端或定时任务开始维护，尚未产生终态通知
- **THEN** 后续监控读取能看到活动维护，而不必等待操作结束

#### Scenario: 启动时容器存在性与样本不同
- **WHEN** 用户提交启动请求，但执行时的容器存在性已不同于监控样本
- **THEN** 按实际状态创建并启动缺失容器，或启动已有容器
- **AND** 已有容器保留其身份和运行配置，不因旧样本选择了创建路径而被重建

#### Scenario: 写入归属仍不确定
- **WHEN** 中断操作尚未确认所属写入进程停止
- **THEN** 监控显示恢复阻塞，冲突修改仍被拒绝

### Requirement: Shared browser observation has a session lifecycle

同一登录应用中的总览、侧栏和详情必须（SHALL）共享一份监控数据及周期刷新入口。操作受理和终态变化必须（SHALL）唤醒相关读取，已有任务事件观察和结果确认继续独立生效。隐藏或离线时必须（SHALL）暂停周期网络读取，恢复观察后重新读取当前状态；会话结束必须（SHALL）清理观察并阻止旧会话响应写入新会话。

#### Scenario: 同时显示侧栏和总览
- **WHEN** 侧栏和总览显示同一服务器，或用户在总览与详情间切换
- **THEN** 它们观察同一份服务器指标，不各自建立重复周期读取

#### Scenario: 接受操作但尚未完成
- **WHEN** 启动、恢复或其他任务已接受但仍在执行
- **THEN** 界面继续展示正在执行及必要保护，不因监控请求成功而报告完成

#### Scenario: 隐藏后恢复或切换用户
- **WHEN** 页面从隐藏恢复，或旧会话退出后建立新会话
- **THEN** 获取当前授权范围内的数据，旧会话迟到响应不能污染新数据

### Requirement: Monitoring work has bounded lifetime

系统必须（SHALL）限制同时进行的采样及待处理工作；慢读取不得（SHALL NOT）导致同一资源的采样无限积压。应用关闭必须（SHALL）停止产生采样并回收已经启动的工作和资源。监控故障不得（SHALL NOT）阻塞独立的任务取消、恢复或健康检查。

#### Scenario: 采样耗时超过计划周期
- **WHEN** 一次采样超过正常更新间隔
- **THEN** 不为同一资源不断启动重叠采样，结果按实际新鲜度展示

#### Scenario: 采样期间关闭应用
- **WHEN** 应用在 Docker 读取或目录统计期间关闭
- **THEN** 停止后续采样并完成已启动工作的清理，不留下无主进程或运行在已关闭依赖上的工作

#### Scenario: 监控源不可用但应用健康
- **WHEN** Docker 不可用或尚无首个监控样本
- **THEN** 独立健康接口仍及时反映应用存活，已受理任务仍遵守原有取消和恢复规则
