## Context

现有路径与保护背景见 `backend/docs/snapshots.md`、`backend/docs/world-restore.md`、`docs/snapshot-recovery.md`，前端观察边界见 `frontend-react/docs/file-operations.md` 和 `frontend-react/docs/data-architecture.md`。忽略解析和所选目标目前都会 canonical 化；历史快照只记录执行路径及展开后的 excludes。直接选择内部符号链接仍操作目标，而父目录遍历时 Restic 存储链接节点。

## Goals / Non-Goals

**Goals:** 按配置名称排除；前后端一致反馈；单个服务器共享一次只读规则查询；维持真实路径边界、锁和写前校验；保留历史保护证据。

**Non-Goals:** 改变显式选择链接时操作目标的行为，为旧符号链接快照或恢复记录转换路径，改造 operations 全局轮询、预览续租、下载、玩家功能或 Restic 本身。

## Decisions

- 逻辑路径与执行路径分离。逻辑路径用于忽略和展示，真实路径用于资源身份及执行；别名不可在逻辑匹配之前合并掉。执行规划保留映射，将所选逻辑范围下的排除后缀转换到执行范围，并在必要的快照/恢复证据中保存映射和语义版本。不同来源的明确历史排除项不得按今天的链接拓扑重新解释。
- 规则读取采用 `GET /snapshots/targets/rules?server_id=...`，返回 `server_id`、`server_generation`、`ignored_paths`（数据目录相对逻辑路径）、`rules_version`。无 Restic 调用、任务提交或操作 journal 写入。`POST /snapshots/targets/check` 仅接收世界选择；不保留文件、项目或全局检查请求及泛用创建请求的备注字段。
- 文件消费者在 backups 特性内共享服务器 query，通过公共逻辑路径判定获得与范围检查相同的 allowed、reason 和 skipped 提示。无周期 timer；打开、重连、显式刷新和相关输入失效按需读取。读取未知/失败保持禁用。
- 配置保存/重置刷新所有规则缓存；文件写入、恢复、填充和服务器代次变化通过现有操作观察及同步 mutation 刷新受影响服务器。首次读取响应与当前服务器绑定，防止串用。
- 世界布局发现、维度展开及 MCA/MCC 关联仍由后端进行；逻辑路径决定忽略，真实路径只决定边界和资源身份。候选快照、来源范围及回滚保护独立校验。
- 多个逻辑选择映射到重叠真实范围时，执行排除必须同时满足各逻辑视图。若一次备份需要排除真实父树又允许其深层子树，底层排除参数无法表达该组合，明确拒绝并提示分别创建快照，不静默丢失允许内容。新源快照记录的链接目标与当前范围不一致时拒绝恢复，避免读取另一实际范围。
- 快照和恢复记录保留已有排除集合，新证据带逻辑范围及映射信息。现有无符号链接记录的逻辑路径与执行路径一致，不需要转换；不增加旧链接记录的排除项、缺失路径或祖先路径兼容分支。证据使用已有 JSON 字段，不增加数据库迁移。

## Risks / Trade-offs

- 同一数据存在多个名称 → 忽略名称不会禁止未被忽略的别名，这属于明确的新契约；并发锁仍按实际目标协调。
- 执行映射丢失逻辑身份 → 所有调用路径与来源覆盖采用统一映射，定向验证两个别名方向和父目录恢复。
- 浏览器缓存过期或外部改动 → 输入失效及重新进入时刷新；执行阶段继续权威重验。
- 源快照排除证据与当前规则不同 → 恢复及回滚继续合并记录的保护集合，不将排除造成的缺失当作删除指令。

## Migration Plan

同时交付前后端规则 API 和世界检查契约，更新 root/backend/frontend AGENTS 与相关设计文档、主规范和 API E2E 覆盖。线上无符号链接数据直接使用已有范围记录，不执行旧链接拓扑转换。只跑直接相关本地测试及必要静态/构建检查；提交推送后完整非发布资格 CI，遵守现有部署与数据库回滚边界。
