## Context

动机和范围见 [proposal.md](proposal.md)。本文件记录已审核的设计约束；实施与验证状态见 [tasks.md](tasks.md)，当前模块结构和交付证据见 [路线图](../../../docs/snapshot-recovery-roadmap.md)。

当前代码已有可复用的基础，不需要重建任务调度和 Restic 封装：

- [快照设计](../../../backend/docs/snapshots.md)：路径规划、当前忽略规则与源快照排除记录的合并、空目录和缺失目标语义。
- [世界恢复设计](../../../backend/docs/world-restore.md)：世界/维度/区域/区块选择、安全快照、附属目录和恢复历史。
- [操作协调](../../../backend/docs/operations.md)：持久化操作记录、资源占用、取消收尾及崩溃后的恢复阻断。
- [数据库迁移](../../../backend/docs/database-migrations.md)：迁移先于运行时生产者启动、单写入者约束。
- [任务中心](../../../frontend-react/docs/task-center.md)与[前端数据架构](../../../frontend-react/docs/data-architecture.md)：任务观察、应用级结果同步和业务功能边界。

主要缺口是编排重复：路径恢复由请求持有执行，缺少完整的业务恢复历史；世界恢复有单独的记录、预览和回滚流程。已有的 Restic 排除规划不能自然约束 mcmap 直接写入、缺失目标清理等所有路径。直接把两套入口包装成任务，会保留这些差异。

## Goals / Non-Goals

**Goals**

- 一个恢复用例拥有受理、范围确认、安全备份、执行、收尾和历史；范围差异通过少量明确分支表达。
- 新旧记录使用同一个历史入口；数据库业务记录和操作日志各司其职，不重复维护执行状态机。
- 操作受理后立即可见，执行阶段和失败原因可读；保留原有界面阻塞范围和关闭限制。
- 保护规则覆盖最终业务数据写入集合，包括 Restic 之外的区块处理和缺失目标清理；派生地图瓦片按明确的缓存维护规则失效。

**Non-Goals**

- 不创建通用工作流引擎、可注册策略插件或第二套任务存储。
- 不将区域/区块安全备份自动扩展为新的手动快照功能；手动世界快照仍支持世界和维度。
- 不将预览变成必经向导，不提供文件系统事务或保证服务器外部进程不能修改在线普通文件。
- 不把全局文件恢复解释为恢复数据库、跨安装迁移或自动重建服务器身份。

## Decisions

### 1. 用明确的范围模型保留业务差别

使用带 `kind` 的范围数据，规范化后记录在恢复历史中。来源入口只用于展示和过滤，不能改变安全规则。

| 范围 | 含义 | 执行差异 |
| --- | --- | --- |
| `global` | 配置的服务器根目录，保留现有全局快照范围 | 全局文件占用，冻结受影响服务器身份与忽略规则 |
| `server` | 单个服务器项目目录，包含 Compose 等项目文件 | 项目范围占用；不能缩减为仅备份 data |
| `paths` | 单服务器 data 下明确的文件/目录 | 普通文件可在线；触及世界数据时采用世界维护限制 |
| `world` | 既有世界选择：整个世界、维度、区域、区块 | 保留多世界布局、region/entities/poi 与 mcmap 语义 |

请求显式指定范围，淘汰“缺少 server_id/paths 推导范围”的执行接口。路径限定、词法路径与真实路径占用继续保留。规范化必须去重父子重叠目标，拒绝越界与符号链接逃逸。

全局范围仍覆盖根目录中的普通内容，不只遍历已登记服务器。受影响的已登记服务器使用确切 generation；全局文件占用阻止执行期间创建、纳管和替换服务器。普通未登记路径由根目录范围保护，不从快照名称猜测服务器身份。源内容不会直接写入应用数据库；后续服务器发现与纳管沿用现有规则。无法确认某条既有恢复记录目标身份时，拒绝其回滚。

选择保留几种范围，而不是强制把区块转换成普通文件覆盖，因为后者会丢失“同一 region 内未选择区块保持不变”的核心行为。

### 2. 共用编排，范围规划与实际写入分开

建议边界如下，文件拆分以职责清晰为准，不为每种范围建立类继承体系：

| 所属位置 | 职责 |
| --- | --- |
| `app/snapshots` 的契约与范围规划 | 请求范围、保护集合、预计影响、持久化范围表示 |
| `app/snapshots` 的应用用例 | 创建、预览、恢复、回滚、删除；统一受理、任务和收尾 |
| `app/snapshots` 的恢复记录存储 | 统一历史、安全快照引用、回滚关系、旧记录读取 |
| 现有 Restic 服务 | 仓库访问、覆盖判断、目录/文件恢复步骤及排除元数据 |
| 世界范围执行模块 | 世界布局展开、区域文件和溢出文件、区块合并与移除 |
| `app/world` 的地图能力 | 布局发现、图层、瓦片、地图渲染，不再拥有第二套恢复编排 |

保留 `DirStep`、`FileStep` 和有意义的空内容处理，不通过不兼容的 Restic include/exclude 组合替换现有规划。世界恢复特有执行代码可以放在 `snapshots/world_scope.py`；它依赖布局和 mcmap 基础能力。避免 snapshots 与 world 的应用层互相导入。

统一恢复阶段为：受理并记录 → 获取资源并再次校验 → 准备源数据 → 安全快照 → 应用 → 清理和缓存处理 → 写入业务结果与任务终态。源准备与安全快照的先后可以按范围优化，但第一笔目标写入必须晚于安全快照引用和缺失状态持久化。

安全快照、子进程及临时目录属于同一个父操作，复用已声明的资源占用。子步骤不能临时扩大范围。不得在长时间 I/O 期间持有数据库事务。

### 3. 一次计算业务数据保护规则，明确缓存维护边界

有效保护集合为：当前忽略设置 + 源快照记录的排除项 + 当前恢复链已保存的必要保护信息。`<LEVEL_NAME>` 根据受理时的实际配置展开并持久化；获取资源后重新校验。配置或实例身份变化导致目标含义变化时，写入前失败，提示重新确认，不能悄悄扩大范围。

- 目标自身位于忽略范围：前端禁用并解释，后端拒绝。
- 目标包含被忽略子目录：允许处理其余内容，一行提示，按需展开跳过路径。
- 创建、安全快照、源准备、实际恢复、回滚、缺失目标删除和空目录清理均使用同一保护结果。
- mcmap 只能处理保护集合之外的实际 region/entities/poi 文件及 `.mcc` 溢出文件。不能只在 Restic 导出时排除，却在合并或删除时写入被忽略目标。
- 所选范围全部受保护是空操作，应拒绝；源中确实不存在的允许目标是有效恢复，可以删除当前对应内容，并可回滚。必须区分“排除了它”和“备份证明它原先不存在”。

地图瓦片是派生缓存。默认忽略 `.mcmap` 表示不从快照备份/覆盖其内容，不禁止恢复后的缓存删除与重新生成。恢复和回滚共用以下规则，沿用现有删除 PNG、后续请求按需渲染的机制，不建立新的缓存版本系统：

| 执行范围与结果 | 缓存清理范围 |
| --- | --- |
| 世界、维度、文件路径恢复正常完成 | 从实际写入/删除事件推导区域，删除对应 PNG；不因选择范围大就全部重绘 |
| 区域恢复正常完成 | 选中区域的 PNG |
| 区块恢复正常完成 | 选中区块按 `(cx // 32, cz // 32)` 归属的区域 PNG，去重后删除 |
| 世界/维度恢复失败或显式取消，变化明细可能不完整 | 扩大到对应服务器/维度的瓦片子树 |
| 区域/区块恢复失败或显式取消 | 选中范围对应区域的 PNG |
| 文件入口涉及世界的恢复未正常完成 | 保留清理受影响服务器全部瓦片的保守策略 |
| 崩溃恢复协调 | 确认写入停止及实例身份后，必要时清理受影响服务器全部瓦片；无法确认时保持既有恢复阻断或缓存降级 |

共用的区域计算将 `region/r.<rx>.<rz>.mca` 变化映射为相同维度和坐标的 PNG；还需覆盖直接恢复/删除 `region/c.<cx>.<cz>.mcc` 的情况，避免仅溢出数据变化却漏掉旧瓦片。后者是对现有只识别 `.mca` 的补漏。`entities` 和 `poi` 变化不独立触发地形瓦片删除；区域/区块选择仍可保守清理整个选中区域。缺失目标清理产生的地形删除也要进入变化集合，不只依赖 Restic 输出或文件时间戳。

删除限于应用拥有的 `.mcmap/tiles` 瓦片，并校验路径归属；不清空整个 `.mcmap`，保留调色板、客户端 JAR 和其他无关内容。正常完成时未受影响区域缓存保留。瓦片请求发现缓存缺失或过期才进入已有渲染队列；地形本身已删除时不生成虚假的空地图。前端在完成、部分失败和取消后刷新相关地图视图，不能因浏览器缓存继续显示旧结果。

缓存清理仍属于受资源占用保护的收尾，任务不能在清理结束前报告成功。删除失败沿用持久化缓存降级与恢复记录，并向用户说明世界数据和缓存各自结果；缓存故障不保留无关服务器的维护锁。观察断线不再取消任务，因此也不能仅因轮询断线触发扩大清理。

相比“每个入口自行处理排除”，这能防止文件和地图出现不同答案；相比一个隐藏所有细节的通用执行器，它仍允许明确检查每种实际写入。

### 4. 复用现有后台任务，受理与完成严格分开

所有可能长时间访问仓库或磁盘的手动操作返回 `202`，包含现有 `task_id`；恢复/回滚另外返回 `restoration_id`。操作日志与任务使用现有统一身份，恢复记录通过唯一的 `operation_id` 关联。任务受理与恢复记录必须一致：排队取消也有可解释的终态，创建失败不能留下永久运行中的记录。

阶段使用“等待执行、检查范围、准备数据、创建安全快照、恢复数据、清理、完成”等用户可理解的文字。有真实字节/项目计数时展示进度；没有时只显示阶段，不伪造百分比。结果、日志和预览摘要有明确大小限制，文件明细分页读取，不往操作日志塞整段 Restic 输出或世界选择大列表。

任务观察读取失败继续重试，并显示“暂时无法获取进度”；不能解除阻塞、重提操作或显示成功。刷新后通过活动任务/操作重新关联界面。观察断开、任务显式取消、进程崩溃是三个不同事件：

| 事件 | 结果 |
| --- | --- |
| 刷新、允许的切页、轮询断线 | 执行继续，重新连接后恢复观察 |
| 用户显式取消 | 停止可终止工作；确认写入停止并收尾后报告取消；已写入内容不自动回滚 |
| 后端崩溃 | 按既有恢复协调记录中断；不自动重放破坏性操作；无法确认写入者停止时保留阻断 |

原先禁止关闭的恢复面板继续禁止关闭。任务中心仍能找到执行中的任务和受影响范围，页面显示具体占用原因，而不是只有灰色按钮。

### 5. 资源冲突保留按业务区分的策略

- 普通非世界文件可以在线恢复；世界数据的任何入口都要求服务器停止，不能通过文件管理器绕过。
- 手动生命周期、重建、定时操作、文件写入和快照操作继续使用现有资源协调。只约束冲突资源，不新增全局读锁。
- 已受理或正在执行的快照创建/恢复/回滚阻止受影响服务器删除，并显示任务。不能因改成后台任务，就让删除自动取消这些数据保护操作。
- 现有可取消区块裁剪仍保留“取消并等待写入停止后删除”的行为。删除先检查快照占用，再进入排他阶段重新检查，避免先取消无关任务再发现冲突，以及检查与实际删除之间的竞态。
- 全局任务根据规范化范围和资源识别受影响服务器，不能仅检查任务单个 `server_id` 字段。
- 定时备份与保留策略复用同一范围、保护和仓库服务，仍由 cron 记录执行。资源冲突时记录 `skipped` 及原因，不伪装成功、不堆积重试任务。

### 6. 统一恢复历史，保留旧数据身份

复用并迁移现有物理 `restoration` 表，由 snapshots 拥有存储；不另建一张仅供文件恢复使用的平行历史表。新增版本化范围、操作关联、入口、回滚父记录、实际影响与保护摘要；全局记录以完整的目标引用集合表达归属，单服务器字段仅作为查询投影。业务历史允许受理/取消等必要结果，但执行状态以操作记录为准，由同一收尾路径更新。

旧世界记录迁移成版本化世界范围，保留原 ID、源/安全快照 ID、selection、缺失目录、world roots、generation、binding_issue 和状态。不根据名称补 generation。对迁移前活跃记录，沿用启动恢复协调确认其状态，不能直接标记成功。历史无法关联旧 operation 时允许为空，不能伪造关联。

已持久化的旧操作恢复引用仍需可解码；删除旧 HTTP 接口不等于删除读取旧磁盘记录的能力。旧文件恢复未保存完整历史，不补造“可回滚”记录；已有操作记录和可验证的恢复引用继续可查。

回滚请求创建新恢复记录，`rollback_of_id` 指向原操作：用原安全快照恢复原范围，先对当前实际允许范围创建新的安全快照。界面简短说明“会覆盖此范围内之后的修改；回滚前会保存当前状态”。源安全快照缺失、实例不符或归属不明时禁用并解释；新增加的忽略范围保持不变，并在结果中列出跳过范围。

活跃任务从受理起保护其源/安全快照，显式删除和保留策略不能删掉执行依赖。预览存活期间也保护其源；过期后释放。已结束历史不永久阻止保留策略删除快照，否则仓库无法按原策略回收。引用消失后历史保留，回滚显示不可用原因。

### 7. 预览是共用契约下的两种呈现

文件恢复展示有界、可分页的增删改摘要；世界恢复保留地图预览。两者使用相同的目标规范化和保护规则，准备过程是任务，不创建安全快照、不改动在线目标，也不写入一条“已恢复”的历史。

预览结果绑定不可变源快照 ID、目标 generation、范围、已观测目标版本和保护规则版本。带预览发起恢复时校验这些信息；应用已观测到的目标变化或规则变化导致冲突，要求重新预览。普通文件在线预览是当时状态的说明，无法保证外部进程随后不修改；实际安全快照以获取资源后观察到的状态为准，不引入整棵目录哈希扫描或虚假的原子保证。

允许保持现有直接恢复流程。未使用预览时仍需要明确范围，并在真正执行前验证受理时的身份与保护规则；预览不承担唯一的安全校验职责。

预览保留现有心跳、每服务器活动会话限制与过期回收，服务重启后过期结果不能继续应用。关闭已就绪预览停止心跳并释放资源；准备中断开观察不隐式取消任务，可显式停止准备。无人观察的结果按 TTL 回收，清理必须等待所属文件读取/写入结束。可能耗时的主动清理使用任务；短心跳和元数据读取保持普通请求。

### 8. HTTP 入口集中，前端功能边界保持直接

以下为目标接口契约，实施时在同一批次调整所有应用与测试调用方，不保留旧同步/SSE 执行适配层：

| 方法与路径（统一 `/api/snapshots` 前缀） | 语义 |
| --- | --- |
| `POST /` | 创建快照，显式范围，返回任务 |
| `GET /`、`GET /usage`、`GET /locks` | 列表、用量、仓库锁读取 |
| `DELETE /{snapshot_id}`、`POST /unlock` | 删除/清理失效锁，返回任务，不能强制清理活跃锁 |
| `POST /eligible` | 根据选择读取可用快照 |
| `POST /targets/check` | 轻量路径/忽略规则反馈，不执行全目录扫描 |
| `POST /previews` | 准备预览，返回任务，结果含 preview_id |
| `GET /previews/{id}`、心跳、瓦片读取 | 已准备的预览元数据与展示资源 |
| `DELETE /previews/{id}` | 释放预览；涉及磁盘收尾时返回清理任务 |
| `POST /restorations` | 恢复，返回 task_id 与 restoration_id |
| `GET /restorations`、`GET /restorations/{id}` | 统一历史，按服务器/范围/状态/入口过滤与分页 |
| `POST /restorations/{id}/rollback` | 回滚为新的恢复任务和记录 |

任务读取和取消复用 `/api/tasks`。静态路由优先于 snapshot_id 动态段；保留现有 cookie/master-token、角色和 CSRF 行为。移除旧路径恢复及世界恢复的创建/预览/执行/回滚/历史路由；与恢复无关的布局、维度标签、领地、玩家位置和地图读取保留。

前端由现有 `features/backups` 暴露契约、命令、历史和通用进度组件；files/worlds 负责选择范围及页面组合。地图预览通过组件组合接入，backups 不反向依赖 world 私有控制器。共用现有任务等待工具和应用级 OperationObserver，完成、失败或取消后按实际修改刷新文件、快照、历史及地图数据，不把刷新责任放在发起弹窗生命周期中。

### 9. 分批实施，每批保持端到端可运行

先建统一范围与记录基础，再成对迁移后端入口和前端调用方；文件恢复、世界恢复各自迁移时就补齐业务测试并删除其旧执行路线。最后合并预览/仓库维护与全面清理。避免先改完全部后端再修前端导致长期不可验证。

每批都执行相关本地验证，再提交分支并运行完整 GitHub qualification。已有测试应调整契约，同时保留原本的业务断言；不能为了绿灯删掉冲突、缺失目录或删除竞态的覆盖。

## Risks / Trade-offs

- **恢复范围与实际写入不一致** → 保护逻辑进入所有文件、区块及清理步骤；用真实 Restic/mcmap 验证受保护内容和未选择区块的字节/数据保持不变。
- **扩大统一模型造成抽象膨胀** → 四种范围、明确分支、一个编排；不预设新存储引擎或任意插件扩展点。
- **旧数据归属不明** → 保留记录和原因、禁用破坏性操作；不凭名称修复身份。
- **旧瓦片漏清理或过度重绘** → 正常执行以变化事件或区域/区块选择计算范围，覆盖 `.mcc` 和缺失目标删除；异常明细不全才扩大清理。派生瓦片删除不受备份排除规则阻止，其他忽略内容仍受保护。
- **取消后部分内容已变化** → 记录实际阶段和安全快照，更新视图，提供明确回滚；不承诺取消等于撤销。
- **普通文件在线状态会变化** → 保留在线能力，以执行前安全快照为恢复依据；预览不承诺文件系统事务。
- **仓库维护阻塞操作或破坏引用** → 有界的活动引用与删除协调，保留 Restic 自身锁；不将所有无关服务器恢复串成单队列。
- **历史规模与全局范围使元数据过大** → 分页查询，完整选择存入业务记录，操作日志保留有界引用；延续现有资源/恢复引用大小上限，超限在受理前明确拒绝。

## Migration Plan

1. 实现前以当前 schema 和真实旧记录建立升级样本，包含成功/失败/运行中世界恢复、缺失安全快照、缺失附属目录、归属不明及同名新实例。
2. 部署前停止接收新任务，排空可完成的操作；不能排空的执行按已有停机协调取消/记录中断，不能在写入者仍活跃时迁移。备份数据库，并记录服务器目录与 Restic 仓库的恢复点。
3. 单写入者启动时先迁移数据库，再执行操作恢复协调，最后开放生产者和路由。同一镜像同时带新前后端；无需 HTTP 向前兼容，不重写 Restic 仓库。
4. 验证旧历史可见、允许的旧记录可回滚、实例歧义被阻止；完成普通文件和世界的创建→预览→恢复→回滚流程，验证被忽略业务内容不变，受影响瓦片被清理并可按需重建。
5. 应用回退必须停机并恢复配套的迁移前数据库。若升级后已有恢复/回滚写入，仅恢复数据库不构成数据回退；必须核对操作记录，并恢复对应服务器文件和仓库引用的配套状态。禁止旧镜像直接写入新 schema，不把此操作伪装成自动数据库降级。
6. 实施完成后同步根、后端、前端、E2E 的 CLAUDE.md 与上述设计文档；文档描述最终真实结构。更新路线图并同步 OpenSpec 规范，完整 CI 通过后再归档变更。

## Validation Strategy

| 业务风险 | 验证方式与期望 |
| --- | --- |
| 同范围不同入口行为不同 | API 与前端用例从文件/地图/全局入口操作；共享保护规则和同一历史记录 |
| 忽略目录被备份或覆盖 | 真实 Restic，当前/历史排除取并集；创建、恢复、安全快照和回滚均验证 |
| 区块路径绕过排除 | 真实 mcmap，检查 region/entities/poi、溢出文件、未选区块和被忽略内容 |
| 原先缺失与被排除混淆 | 空源删除允许目标；回滚还原原先缺失状态；保护目录永不因此被删 |
| 地形已恢复但地图仍旧，或无关地图被重绘 | 正常完成仅清理受影响区域；覆盖负坐标、跨区域区块、仅 `.mcc` 变化与地形删除；保留未受影响瓦片、调色板及 JAR |
| 忽略缓存目录阻止必要失效，或异常留下旧图 | `.mcmap` 被忽略仍删除受影响 PNG；失败/取消/崩溃按范围保守清理，删除失败记录降级；下一次请求才触发渲染 |
| 获取任务 ID 后界面提前放行 | 前端延迟受理/排队/读取失败/终态用例；原关闭限制一直保持到真实终态 |
| 刷新和断线取消任务 | API 与浏览器观察中断后任务继续；重新观察恢复进度及阻塞状态 |
| 部分失败与取消 | 注入阶段故障，检查安全快照、历史、实际文件、缓存与释放时机一致 |
| 维护冲突和删除竞态 | 保留最近 CI 修复的快照拒绝删除与裁剪取消后删除；加入排队/全局任务竞态 |
| 预览过期或目标变化 | 身份/范围/保护版本不符拒绝应用；临时资源和活动引用最终回收 |
| 保留策略删掉执行来源 | 活动恢复/预览期间拒绝删除；结束后允许回收，历史解释回滚不可用 |
| 旧数据升级与重启 | 迁移真实旧 schema；崩溃不重放；身份不明不写入；失效地图缓存不继续读取 |
| 接口迁移遗漏 | 全部 API E2E、浏览器、认证/CSRF、静态检查及完整镜像 qualification |
