# 快照与恢复系统

文件管理器、地图和快照管理页共用创建、预览、恢复、回滚及仓库维护流程。实施范围保存在归档 [任务清单](../openspec/changes/archive/2026-10-06-unify-snapshot-recovery/tasks.md)；[行为规范](../openspec/specs/snapshot-recovery/spec.md) 是后续改动的验收依据。设计取舍与测试矩阵保存在归档 [详细设计](../openspec/changes/archive/2026-10-06-unify-snapshot-recovery/design.md)。

## 用户可见的行为

- 耗时操作受理后立即显示任务阶段；进度未知时显示阶段说明，不编造百分比。原本阻塞的界面继续等待真实终态，任务 ID 或 100% 进度不等于完成。
- 文件和地图恢复共享历史、源快照、安全快照、服务器实例身份和回滚关系。历史可以按范围、结果和入口筛选。
- 刷新或允许的切页不取消后台执行；重新进入后恢复观察。状态读取失败显示重连提示并保持阻塞，完成结果保留到用户关闭。
- 每次恢复先保存安全快照和缺失状态，再修改目标。每次回滚都是一次新的恢复，也先保存当前状态，因此还能再次回滚。
- 回滚会覆盖选中范围内后来的修改，不是逐条撤销差异。失败或取消不自动重试、不自动回滚，保留实际修改与安全依据供核对。
- 普通文件保留在线恢复能力；涉及世界数据的文件路径与地图选择都要求停服。不同入口不能绕过身份、路径和冲突检查。
- 文件列表与高级搜索将多个实际路径组成一次任务范围，共享预览、安全快照和恢复历史；未选路径保持原有内容。
- 所有手动创建入口可填写最长 500 字的备注，快照管理页可编辑，列表和恢复选择器显示同一内容。备注保存失败仍保留已创建快照及其 ID，可只重试保存备注。

## 模块边界

后端 `app.snapshots` 拥有范围契约、忽略保护、任务受理、恢复历史、预览寿命和仓库引用。`app.world` 保留世界布局、选区规划、mcmap 合并、地图副本及缓存收尾。普通文件替换和区块合并使用各自清晰的执行代码，共享安全与历史规则。

前端 `features.backups` 拥有公共契约、命令、任务观察、预览、历史和进度组件。文件管理器与地图通过组合使用这些入口。`FileSnapshotRecovery` 在文件页只挂载一次，不由每一行各自持有恢复会话。应用级操作观察负责跨页面刷新相关缓存和地图 URL 版本。

手动全局、项目、data 路径及世界范围含义保持独立：项目备份包含项目文件，文件管理器根目录指向 data。定时备份使用公共命令，保留 cron 的独立执行历史和 `skipped` 结果。

## 忽略目录

手动创建、预览、安全快照、恢复、回滚和业务数据清理都遵守保护规则。恢复采用当前设置、源快照排除记录及恢复链保护信息的并集，冻结 `<LEVEL_NAME>` 的实际展开；旧快照缺少被排除内容不代表应删除在线内容。

| 用户选择 | 行为与提示 |
| --- | --- |
| 目标本身位于忽略范围 | 禁用创建与恢复，显示原因；直接提交也被后端拒绝 |
| 父目录包含忽略子目录 | 处理允许内容，显示一行跳过说明 |
| 全部选中内容均被保护 | 拒绝无可操作范围的请求，不制造成功结果 |
| 源能证明允许目标原先不存在 | 可以恢复到不存在的状态，并保留再次回滚能力 |
| 源快照完整排除任一选中根路径 | 不作为该多路径范围的恢复候选；目录内部的排除仍保留跳过语义 |

路径别名、缺失目标删除、空祖先清理、实体/POI 附属数据和溢出 MCC 文件同样受保护。被忽略的 MCC 与其 MCA 中的区块入口作为同一单元保留。

## 快照备注

备注随应用数据库保存，以 `restic cat config` 的实际仓库 ID 和完整快照 ID
关联；旧快照默认空备注。同一路径重新初始化的仓库与原仓库隔离。编辑备注不会修改
Restic 标签、快照内容或 ID，也不会改变恢复历史和已就绪预览的引用。
应用数据库备份需要包含备注元数据；仅备份 Restic 仓库不会保留备注。

## 地图缓存

恢复后删除对应区域缓存是预期行为。`.mcmap` 被忽略只限制快照内容，不阻止应用清理自己生成的 PNG。

- 正常世界、维度及文件恢复按实际地形变化清理；区域和区块恢复按选区映射、去重。单独 MCC 变化、负坐标及地形删除都能使对应瓦片失效。
- 无关区域 PNG、调色板和客户端 JAR 保留；后续地图请求按需生成瓦片，不立即重绘整张地图。
- 写入后失败、显式取消或崩溃导致变化范围不确定时，可扩大到受影响维度或服务器。观察断线本身不触发取消或扩大清理。
- 缓存清理失败会显示并记录降级，不能报告全部成功。浏览器瓦片 URL 同时带 MCA mtime 和操作版本，避免 MCC 单独变化或相同 mtime 恢复后继续显示旧图片。

## 预览与并发

文件动作预览和地图预览都由任务准备，不写在线目标，也不产生恢复历史。准备成功后使用心跳和有限有效期；关闭、替换或过期会等待所属读写结束再清理资源。预览绑定源、实例、范围、保护规则及应用已观测的目标变化，按预览恢复前必须复核。直接恢复仍可使用，在线预览不承诺阻止外部程序修改文件。

任务从受理到收尾都持有目标与仓库引用，排队阶段也受保护。有效预览保护源快照，仓库删除和保留策略不能破坏活动依赖；终态历史不会永久阻止正常回收，所需安全快照被回收后会解释回滚不可用的原因。

服务器删除在受理前及排他阶段检查快照冲突，包含全局任务。允许取消的裁剪仍可由删除流程停止并等待清理；无法确认写入者停止时保留恢复阻断和资源，不猜测安全状态。

## 升级与交付边界

数据库迁移 `2026093000` 扩展原 `restoration` 表，保留旧 ID、快照引用、selection、缺失证据和已知服务器代次。旧记录身份明确且安全快照存在时可回滚；歧义或同名新实例不重新猜测归属。未保存过完整安全信息的旧文件操作不会被伪造为可回滚历史。

迁移 `2026100600` 创建 `snapshot_notes` 表，复合主键隔离实际仓库和完整快照。
已有恢复历史、任务结果与快照仓库无需迁移；备注修改不重写这些记录。

前后端必须同时部署；被替换的同步/SSE 快照执行接口已删除。真实发布版 `v6.0.0-beta.1` 的升级与配套回退使用 [隔离部署演练](../e2e/docs/deployment-rehearsal.md)。升级后的 schema 不支持直接运行旧发布版；有恢复历史时也拒绝数据库降级。完整检查点灾备只恢复检查点时刻，不合并其后的修改，后续数据必须另行保留。

每次变更均须按[交付与测试要求](../AGENTS.md#交付与测试要求)完成本地定向验证、commit/push，并对最新 SHA 运行完整 qualification；部分检查或旧 SHA 的通过不能代替最终验收。分支合并、发布及 OpenSpec 归档分别按用户授权执行。
