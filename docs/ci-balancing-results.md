## 调度与证据

本次完整运行观测到最多八个成功 job 同时占用 runner：四个后端分片、三个 API 分片和浏览器。基线的主要限制是后端矩阵明确设置的串行执行；这些记录不能证明账号的并行额度上限。其他仓库工作流仍可能竞争 runner。

所有成功 job 的累计运行时间（排除发布）从 84:29 降至 57:57。该值不是墙钟时间或精确计费分钟，也不包含开发过程中的失败尝试。

完整运行提供以下可下载 artifacts，保留期以 workflow 配置为准：

- `backend-test-reports`：逐测试 `test-durations.csv`、阶段 JSON、JUnit、原始及合并覆盖率。
- `backend-test-inventory`：完整清单、分片计划、策略与历史权重身份。
- `e2e-results-1/2/3`：每项 API 用例的执行、队列等待、资源等待、准备、断言、清理和环境销毁时间。
- `browser-results`、`frontend-test-results`、`go-test-results`：浏览器、Vitest 和 Go 的逐项结果与时间。
- 资格证明及候选产物：源码、镜像身份和各测试门禁的一致性证据。

首轮验证曾发现 ShellCheck 重定向问题和一个真实界面缺陷：地图初始化切换侧栏结构，导致已打开的恢复历史抽屉卸载。两者均已修复并通过第二轮完整 CI；未通过放宽断言、延长超时或跳过场景来获得成功。

目前剩余长尾是单个世界恢复文件及部分 Minecraft 场景。后续应积累多次成功运行的精确计时，再审查文件拆分或更新历史权重。新测试始终由完整清单发现，历史权重只影响分配位置，不控制测试是否执行。E2E 调度器变更还需按[运行说明](ci.md)执行禁用复用的隔离验证。

## 取消竞态修复与最终验证
