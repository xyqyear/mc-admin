# 快照与恢复系统：下一轮需求记录

状态：待实施。本轮只改造非快照耗时操作的后台任务接入；本文件不代表已经改变快照行为。

## 用户目标

文件管理器、地图页面和其他入口共用一套快照与恢复系统。用户不需要理解入口背后存在不同的恢复实现，也不应该因为换了入口就失去安全快照、历史记录或回滚能力。

代码应当直接、容易阅读。复用现有任务管理、操作记录、资源锁和 Restic 能力；不要另造调度框架，也不要为了统一而把所有业务塞进一个庞大的管理类。

## 改造顺序

1. 完成 `openspec/changes/background-non-snapshot-operations/` 中的非快照耗时操作改造。
2. 再为快照与恢复建立独立 OpenSpec 变更，核对本文件并细化历史兼容、取消和回滚行为。
3. 第二轮才改造快照创建、恢复、恢复预览、回滚和相关维护任务；第一轮不改动这些入口的执行归属与接口语义。

## 统一的内容

- 一个公共的创建、恢复和回滚流程，统一受理、后台执行、阶段反馈、失败处理和结果查询。
- 一个用户能理解的历史视图，能够识别来源入口、服务器、目标范围、源快照、安全快照及操作结果；同一操作不因入口不同生成两份互不关联的历史。
- 文件和文件夹范围与世界、维度、区域、区块范围使用各自清晰的范围规划代码，共享执行流程。区块合并和文件恢复仍保留必要的业务差别。
- 恢复前的安全快照、失败后的恢复路径和回滚关系采用一致规则；普通文件恢复也应有可以发现的撤销入口。回滚前再次保存当前状态，避免回滚成为不可撤销的操作。
- 普通文件能够在线操作的行为继续保留；涉及世界数据的停服要求、路径限制、服务器实例身份校验和锁保护继续保留。
- 后台任务负责执行，页面通过任务状态展示进度。原来阻塞界面的流程仍然阻塞，原来流式展示进度的页面保留展示和关闭限制，只替换状态来源；拿到任务 ID 不代表完成，不提前解除禁用或关闭面板。第二轮明确刷新、允许的切页、显式取消和后端重启的含义；意外断开观察不隐式取消已受理的恢复任务。

## 忽略目录的规则

手动创建快照和手动恢复必须遵守忽略目录设置，文件管理器和地图入口使用同一套判断。安全快照、回滚及区块执行也不能绕过该规则。

| 用户选择 | 预期行为 | 建议提示 |
| --- | --- | --- |
| 目标本身就是忽略目录或位于其中 | 不允许创建快照或恢复，后端也拒绝直接请求 | 禁用相关按钮，并说明“此路径已被快照规则忽略” |
| 目标包含被忽略的子目录 | 允许操作，但跳过忽略范围 | “将跳过已忽略的目录，其他内容正常处理” |
| 恢复范围包含受保护目录 | 不覆盖、不删除该目录及其内容 | “已忽略的目录将保持不变” |
| 没有可操作内容 | 不生成看似成功的空操作 | “所选范围没有可备份／恢复的内容” |

界面优先使用一行说明；有必要时再展开被跳过的路径，不新增复杂确认向导。禁用而非隐藏按钮是初步建议，最终按页面布局决定。后端判断始终为准，不能只靠前端隐藏按钮。

现有 `backend/docs/snapshots.md` 已描述当前忽略设置与快照记录的排除项共同保护恢复范围。这一保护不能在统一过程中丢失；历史快照缺少某项内容也不能被误解释为“应当删除被忽略目录”。目录恢复、空目录清理、区域文件恢复和区块合并都需要验证。

## 下一轮需要具体落实的设计

- 沿用当前 Restic 快照与已有世界恢复历史，明确旧记录的显示、可回滚性和服务器实例归属；不靠服务器名称重新猜测历史绑定。
- 在统一流程中区分“目标范围”与“实际被覆盖的数据”，保留恢复原先不存在的文件、目录或区块的能力。
- 为文件恢复接入统一历史与安全快照引用，明确删除快照后哪些回滚操作不可用。
- 明确预览结果是否需要重新验证、忽略配置变化后如何反馈，以及进度阶段与任务结果的展示。
- 保留“回滚是恢复指定范围的先前状态”的真实含义：该范围内此后产生的数据也可能被覆盖，不将其描述为差异撤销。
- 不用自动重试或自动回滚掩盖部分失败。后台任务终态、数据是否已变化、失败发生在哪个阶段，应当相互一致。

## 验收方向

同一范围从文件管理器或地图进入时，采用一致的忽略规则、任务状态和历史关系；各入口原有的阻塞范围和关闭限制保持不变。允许的切页或浏览器刷新不终止已受理的操作，返回后按实际任务状态恢复进度及阻塞状态；任务状态读取失败不能被当作任务完成。忽略目录中的内容在成功、失败、取消、空目录清理及回滚后都保持受保护状态。现有快照仍能被识别，旧世界恢复记录仍可读取，安全快照存在且身份明确的记录保留回滚能力。
