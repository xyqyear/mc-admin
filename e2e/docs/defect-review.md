## 本轮修正的测试材料与策略

- `auth.code-login-and-csrf` 使用实际生成并完成登录的 code/ticket，检查普通容器日志及审计，且要求成功请求的对应字段确实被替换，避免只因没有日志而通过。完整值检查之外，还检查至少 12 字符的票据前后片段和原始凭据帧，失败证据也对这些片段脱敏。
- `system.audit-redaction` 在 DNS 禁用时通过真实配置接口保存并读回测试 ak/sk，再检查审计；没有访问云端。嵌套额外字段只用于验证中间件递归，不代表供应商完整工作流。
- `audit.sensitive_exact_fields` 是可配置列表，默认 ak/sk/code/ticket；原 sensitive_fields 保留子串语义。精确匹配避免把 task_id/status_code 误屏蔽，但部署自定义名单仍需覆盖其秘密字段。
- Linux 反斜杠是普通文件名字符。之前的额外禁止规则已移除，真实文件 CRUD 用例覆盖该兼容性；目录穿越和外部符号链接仍被拒绝。
- 禁止删除／重命名受管数据根目录，以及 multipart 开始写入前验证所有目标，是明确保留的操作策略，不能各自算作修改前独立复现的漏洞。合法上传仍有逐文件结果，写入期间的文件系统失败不保证整批回滚。
- 路径解析后检查不构成抗并发符号链接替换的完整沙箱。任务取消仍是协作式，也不承诺清理任意进程树或在文件系统拒绝删除时消除输出。

## 不应列为产品缺陷的失败

| 原测试预期 | 正确判定 |
| --- | --- |
| 删除重启计划后查询应为空 | 原计划是软删除；检查 cancelled 和 next_run_time 为空 |
| 同 ID 再次创建计划必须冲突 | 原接口采用创建或更新语义 |
| 手动创建系统自检计划应成功 | 系统任务类型受保护，409 符合原约定 |
| 区块清理后区域文件必须消失 | 空区域文件可以保留文件头，应核对区块内容 |
| 预览应在无调色板时工作 | 用例需要初始化实际依赖的调色板 |
| UID 65534 可以直接用于 Minecraft 镜像 | 测试账户与镜像已有 UID 冲突，应使用兼容的隔离账户 |
| 访问正确但覆盖报告未计数 | 原采集器读取了父应用 Schema，路径匹配还漏掉参数后缀，属于 E2E 框架错误 |
| Docker 输出无法解析为镜像 ID | 标准错误中的警告被混入标准输出，属于框架解析错误 |

上述测试预期和框架问题按其各自契约调整，不通过改变正常后端行为来迎合错误断言。

## 保留的未决语义与验证限制

DNS 地址或可读取服务器集合为空时，当前管理器跳过同步，差异查询失败。原代码和原测试均明确保留这个行为；它可能防止临时配置缺失导致误删，也可能在用户删除最后一个目标后留下记录。需要区分明确清空与无法取得目标，本轮没有改变该语义。

DNSPod／华为 DNS 缺少专用测试域名凭据，云端资格验证仍未执行。真实 mc-router 客户端通过、禁用 DNS 配置提交通过，都不能替代云端记录变更或 Minecraft 代理流量验证。

Quilt 与日志等确定性文件是公开格式测试输入；实际 Minecraft 启动、RCON 和世界数据由对应真实运行用例验证。任务中心权限矩阵覆盖本轮发现的缺口，不能推断整个应用所有输入、权限和并发组合已经穷尽。
