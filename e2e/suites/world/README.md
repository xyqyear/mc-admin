# World regression scenarios

These scenarios run the deployed API with real Minecraft, mcmap and Restic. Each case owns a fresh environment. Cases that only require public world formats use deterministic NBT/Anvil inputs without starting Minecraft; the relevant mcmap or Restic executable still runs in the real application image. A scenario may reuse its own snapshots across related operations, with explicit before/after byte assertions; no scenario depends on another case's data or order.

| Case | Observable behavior |
| --- | --- |
| `world.map-render-and-cache` | Discover a saved real world, reject unsafe/missing paths, initialize the real client jar and palette, reuse and force-regenerate prerequisites, serve concurrent 512×512 PNG requests, refresh a stale tile and its ETag. |
| `world.claims-and-player-locations` | Extract SNBT FTB teams and disconnected claim clusters, preserve force-loaded chunks, resolve present dimensions and retain unresolved dimensions, read gzip player NBT, report malformed files, serve both aliases, read dynamic dimension labels. |
| `world.legacy-layout-and-extractors` | Discover multiple roots and legacy/custom/deep dimensions; extract LatMod JSON, universe.dat and per-team gzip NBT; enforce format precedence, name fallback, legacy player storage, missing-field skips and missing-server responses. |
| `world.scoped-restore-and-rollback` | Create world/dimension snapshots, select eligible snapshots, stage all four preview scopes without mutation, restore and undo chunks/regions/dimensions/worlds, preserve boundaries across terrain/entities/POI files, restore additional world roots, paginate history, and reject rollback after safety-snapshot deletion. |
| `world.preview-lifecycle` | Render real preview PNGs, heartbeat, replace the prior session, reject out-of-scope tiles, end idempotently, enforce the disk guard, expire a session through the real janitor. |
| `world.chunk-prune` | Read defaults and latest task state, reject invalid requests and running-server apply, execute both preview/apply modes, verify polygon geometry and claims protection, inspect resulting Anvil chunk tables, cancel a running preview. |
| `world.prune-preview-validity` | Reject changed world/claim inputs, expire a preview through its dynamic TTL, retain data on rejection, apply a new preview with actual claim protection, reject repeated application and retain its unique task identity. |
| `world.prune-dismiss-active` | Pause the owned real mcmap apply; dismiss the completed preview from the task center while retaining its claim file, geometry and feature projection; reject another apply and active-task dismissal; resume the original writer and verify contents. Restart rejects use of previous-process preview artifacts. |
| `world.restoration-generation` | Restore through real Restic, recreate the same server name, retain old history and safety references, reject its rollback without changing new data, preserve the refusal after restart, and allow a current-generation restore. |
| `world.empty-scope-rollback` | Snapshot an empty region directory through real Restic, add live MCA files, restore the empty dimension or selected region, roll back to the exact live bytes, then undo that rollback to recover the empty scope; unselected regions and ordinary files remain unchanged. |
| `world.interrupted-restore-recovery` | Observe operation-lock rejection, kill only the owned backend during a persisted restore, restart the deployment, verify interrupted history and restore original bytes through safety rollback. |
| `world.missing-sidecars-and-rollback` | Restore nonempty entities/POI after deleting their entire directories through the API, across world/dimension/region/chunk scopes, then verify rollback removes only the restored scope and reinstates directory absence. |
| `world.delete-waits-for-writer` | Pause an owned real mcmap writer, verify deletion freezes new writes, then require the application to terminate the writer before deletion succeeds; observe the owned process and project and retain ordered cancellation/deletion history. |
| `world.disconnect-restore-and-maintenance` | Keep ordinary file restore available online, require stopped state for whole-server restore, expose maintenance and reject startup/rebuild/deletion/global backup during restore, reject overlapping file CRUD/upload while allowing unrelated file writes/restores, record scheduled restart as skipped, close only SSE and verify terminal interrupted history and safety rollback without backend restart. |
| `world.safety-snapshot-disconnect` | Close real SSE immediately on its first nonempty safety snapshot ID; require matching terminal restoration/operation identities, stopped writers and released maintenance; persist independent configuration and cron changes; overwrite live data and then recover the exact pre-request bytes through safety rollback without restarting the backend. |

`assets.go` and `legacy.go` generate small public-format NBT, gzip, Anvil and SNBT inputs. Fixture writes are restricted to the case's owned server data directory and recorded as evidence. They neither import application code nor replace Minecraft, mcmap, Restic or API implementations. Map rendering uses the world generated by the actual Minecraft server; selective restore and pruning additionally use small deterministic region fixtures so exact chunk boundaries can be checked.

The format layouts were checked against the deployed mcmap v0.8.4 source (`ac6e5e23f02910994d4a515f1c25ac1c0bd1d1e4`). Format detection and extraction are always performed by the real binary in the application image. No source checkout is needed when running the tests.

Preview expiry first locates the existing session directory under the owned runtime's private scratch root, then observes its removal before its final API assertion: both heartbeat and tile requests extend session lifetime. Restic crash recovery observes the streamed `restore` phase after the history row is persisted before sending SIGKILL, then uses the normal backend restart and rollback APIs.

The disconnection scenario pauses real Restic child processes in the owned backend container with SIGSTOP: backup holds the maintenance window for API checks, then a post-history-insert ls holds the cancellation point. It resumes backup explicitly; the application must terminate and reap the paused ls on disconnect. Every signal checks the container root, command and process start time through a pidfd to prevent PID reuse; case cleanup resumes recorded surviving processes and stops the observer. No replacement CLI or application delay is used.

The separate safety-snapshot disconnection scenario closes the socket at the earlier persisted safety event, without waiting for a Restic process or inserting a pause. It uses one attempt in a fresh Backup environment. An interrupted result and a successful restore that finishes before the socket closure are both legal. A completed restoration may retain a conservatively interrupted request journal if the disconnect arrives after data finalization but before the final response; both outcomes are recorded separately. History and its exact journal operation must have end timestamps and known stopped writers, and release maintenance. Failed or permanently running histories cannot pass, and interrupted data history cannot pair with a successful operation. This public transport scenario does not claim to force cancellation inside a specific SQLite instruction; backend cancellation tests control that transaction boundary. Independent database mutations and a subsequent byte-checked rollback ensure cancellation cannot strand SQLite locks, and replacing live bytes after disconnect prevents a no-op rollback from passing.

The deletion scenario also leaves its real mcmap writer stopped until the application cancels it. It requires HTTP 200 only after the task is cancelled, its original process identity is gone, and operation history confirms stopped writers before successful deletion. An observer rejects removal of the owned project while that process is still alive. The case does not resume the writer to make deletion pass.

The dismissal scenario uses the same owned-process observation, but explicitly resumes that original writer after dismissing the completed preview. While the writer is paused, its actual `--exclude-ftb-claims` path and SHA256 must remain unchanged. This checks the live artifact lease even if mcmap has already read the claims file. The freshness scenario observes API-provided expiry time without altering clocks or persisted metadata. The pinned mcmap recomputes its predicate on apply; these assertions qualify the application's input validation and resource ownership, not a frozen selection list or protection from arbitrary external file writers.
